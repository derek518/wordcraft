## 流程

```bash
# 1. 提示词（永远从文档派生，不要手抄）
python3 scripts/cards/build_prompts.py > scripts/cards/card_prompts.tsv

# 2. 生成 1024×1024，原图放 <某个暂存目录>，文件名与 TSV 第一列一致

# 3. 压制
python3 scripts/cards/conform.py <暂存目录> -o wordcraft/public/assets/cards/rare
```

`conform.py` 会顺带清除左下角的「AI生成」灰度水印，并逐张报出主体占比与色数。
出现 `⚠ 几乎画满` 通常意味着背景没抠干净。

## 验收

- 文件名与 TSV 第一列**逐字一致**。`010_card_pool_v2.sql` 的 `image_path` 与它们
  一一对应，改名的后果是卡面空白且不报任何错
- 尺寸 256×256（卡面）/ 64×64（界面），RGBA，全透明底
- 边框、名牌、稀有度装饰**不要画进图里**，那些是代码合成的
- 把成品排成联络表扫一遍：缩略图大小下两两可区分
- 不出现任何商业游戏 / 动漫 IP 的名称或可辨认形象。提示词里一个都不要写

## 一件与素材无关但同样重要的事

`npm run dev` 现在有正式的假数据模式，不要再往组件的 `catch` 里塞 mock：

```bash
VITE_MOCK=1 npm run dev
```

假数据统一在 `src/data/devMock.ts`，接在 `api.ts` 的 `call()` 最前面做**前置替换**。
缺哪个 command 就去那里补一个 handler，它会明确报错告诉你缺哪个。

为什么不能放在 `catch` 里：那样后端一坏就自动展示假数据，真实故障被完整盖住。
迁移 010 崩溃那次，要不是应用整个起不来，看到的就会是一屏漂亮的假卡。
